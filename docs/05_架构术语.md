# 群智 · 智能体架构设计（术语凝练版）

> **用途**：回应评审意见第 1、2 条——「部分设计文档专业性不强」「用专业术语修改设计文档，进一步凝练智能体架构设计」。

## 一、系统定位（形式化表述）

群智是一个**面向决策预演的异构多智能体系统**（Heterogeneous Multi-Agent System for Decision Rehearsal）。

给定课题 $q$ 与用户初始立场 $u$，系统实例化一个角色集 $\mathcal{A} = \{a_1,\dots,a_6\}$，在**受控信息不对称**条件下执行 $R$ 轮结构化协商，输出决策预演报告 $y$ 及其证据链 $E$：

$$
y, E \;=\; \Phi\big(q,\; u,\; \mathcal{A},\; \mathcal{I}\big),
$$

其中：
- $\Phi$：编排函数（由引擎层实现，见 §2）
- $\mathcal{I}$：主教练注入的信息池（由检索层构造，见 §2.4）

**与通用对话式 Agent 的差异**：通用 Agent 优化的是"回答质量"；本系统优化的是**决策者在信息不完备条件下的盲区发现率**，因此核心机制不在生成端，而在**角色配置**与**信息分配**两端。

## 二、五层架构（职责 / 接口 / 依赖）

| 层 | 名称 | 职责 | 对外接口 | 关键依赖 |
|---|---|---|---|---|
| **L5** | 表示层 Presentation | 会话驱动、流式渲染、结果可视化 | HTTP + SSE | 原生 HTML/JS，无前端框架 |
| **L4** | 接入层 Gateway | 请求校验、限流、会话生命周期、插件路由 | REST（FastAPI） | pydantic 契约校验 |
| **L3** | 编排层 Orchestration | 讨论状态机、干预决策、评审调度 | 进程内调用 | 自研编排器，**不依赖 LangChain / AutoGen** |
| **L2** | 知识层 Retrieval | 多源检索、质量闸门、相关性排序、证据池构造 | 函数级 | **仅 requests**（无向量库、无嵌入模型） |
| **L1** | 数据层 Persistence | 会话落盘、审计日志、复算数据 | 文件级 | JSON / JSONL，无外部数据库 |

**依赖方向严格单向 L5 → L1**，无反向依赖；L2 可被 L3 按需调用，也可独立作为检索服务运行。

## 三、核心机制的形式化描述

### 3.1 角色配置：三层正交属性

每个 Agent 由三元组定义：

$$
a_i = (\pi_i,\; d_i,\; v_i) \in \Pi \times D \times V
$$

| 属性 | 语义 | 取值空间 | 作用 |
|---|---|---|---|
| $\pi_i$ **认知原型** | 信息加工偏好 | $\|\Pi\| = 7$ | 决定**先看什么**（机会 / 风险 / 约束…） |
| $d_i$ **专业领域** | 领域知识先验 | $\|D\| = 8$ | 决定**看哪些变量** |
| $v_i$ **价值取向** | 冲突时的偏好序 | $\|V\| = 6$ | 决定**在冲突中保什么** |

**理论配置空间** $|\Pi \times D \times V| = 7 \times 8 \times 6 = 336$。

> ⚠ **术语使用纪律**：336 是**配置空间的基数**（cardinality），不是"能力"或"优势"。实测人格维度主效应 $d \approx 0.05$（可忽略；⚠ 该值来自已作废评审库，不作结论）。**有实证支持的是"角色之间应当存在差异"（认知异构），而非"某一组配置更优"。** 材料中一律不使用"336 种思维路径""336 种智能"等表述。

### 3.2 信息分配：受控信息不对称

设信息池为 $\mathcal{I} = \{P_1,\dots,P_n\}$（$n$ 条证据，编号可引用）。第 $i$ 个 Agent 在第 $r$ 轮的可见信息为：

$$
\mathcal{I}_i^{(r)} = \alpha_i\big(\mathcal{I};\; i,\; r\big), \qquad \bigcup_i \mathcal{I}_i^{(r)} = \mathcal{I},\quad \mathcal{I}_i^{(r)} \neq \mathcal{I}_j^{(r)} \;\;(i \neq j)
$$

**约束**（"两层盲区"的技术定义）：
1. **成员间盲区**：任意两个 Agent 的可见集不完全相同（$\mathcal{I}_i \neq \mathcal{I}_j$）；
2. **人机盲区**：用户初始立场 $u$ 不含 $\mathcal{I}$ 的任何内容，即 $\mathcal{I} \cap \mathrm{supp}(u) = \varnothing$ 近似成立。

**为什么这是必要机制**：若 $\mathcal{I}_i \equiv \mathcal{I}$（全员共享同一信息集），协商退化为**同分布重复采样**，输出方差趋零、信息增益为零——这正是"多开几个 AI 仍得到一致平庸答案"的成因。

### 3.3 干预策略：基于客观信号的条件触发

主教练不是主持人，而是一个**策略函数**：

$$
\text{intervene}(r) =
\begin{cases}
\text{act}_k, & \text{if } \exists\, k:\; s_k^{(r)} > \tau_k \\
\varnothing, & \text{otherwise}
\end{cases}
$$

其中 $s_k^{(r)}$ 为第 $r$ 轮第 $k$ 类**可计算信号**，$\tau_k$ 为阈值。

| 信号 $s_k$ | 计算方式（本地、确定性） | 对应动作 $\text{act}_k$ |
|---|---|---|
| 术语漂移 | 核心术语在不同发言中的语义不一致度 | 概念冻结 |
| 未补证断言数 | 无引用且未标"待验证"的断言计数 | 证据追问 |
| 张力—收敛失配 | 分歧度高但结论数不增 | 分歧聚焦 |
| 维度覆盖空缺 | 某专业维度连续 $m$ 轮无发言 | 视角补位 |
| 观点重复率 | 相邻发言的 $n$-gram 重合度 | 冗余压缩 |
| 跑题度 | 发言与课题的词汇/语义距离 | 跑题拉回 |
| 单向乐观 | 负面表述占比低于阈值 | 风险预警 |
| 轮次将尽 | $r \to R$ 且结论未成形 | 收束定稿 |

**两个设计要点**：
- **信号全部本地可算**，不依赖模型"感觉"，因此每次干预都能给出触发依据（可审计、可复现）；
- **触发时点为 per-round**（逐轮判定），而非固定轮次无条件注入；**"本局未触发干预"同样是合法且可报告的结果**。

### 3.4 评审契约：结构化判定

评审器为**独立插件**（可替换），遵循统一契约：

```
Judgment := {
  dimension : str,
  score     : float ∈ [1,10],
  confidence: float ∈ [1,10],
  evidence  : str,          # 必须引用报告原文，否则该维度作废
  verdict   : bool | null   # 可选布尔判定（如 is_genuine_emergence）
}
```

**三条硬约束**：
1. **无证据不计分**——`evidence` 为空则该维度记为无效，不参与聚合；
2. **锚点自检前置**——评审器自身须先通过"尺子体检"（完整报告应胜过删节 60% 的同文；同一份应判无差别），**未通过则不出任何分数**；
3. **同源披露**——若评审模型与生成模型同族，报告须显式标注"评审与生成同源，仅供参考"。

### 3.5 证据链：从注入到引用的可追溯性

每条证据 $P_k$ 携带结构化元数据：

```
Evidence := {
  ref_no, title, authors, journal, year, journal_level,
  doi, url, abstract, source_tier
}
```

报告正文中的引用标记 `[Pk]` 由**代码生成并核验**，不由模型自由生成。核验器检查三类问题：
- **越界引用**：引用了不存在的 $P_k$；
- **幻觉数字**：正文出现具体数值但信息池中无对应来源；
- **依据缺失**：结论句无 `[Pk]` 且未标"待验证"。

## 四、关键设计决策（及其技术理由）

| 决策 | 选择 | 理由 |
|---|---|---|
| **编排层自研**，不用 Agent 框架 | 自研状态机 | 框架的隐式行为（自动重试、隐式上下文注入）会破坏**可审计性**；预演系统必须能回答"第 r 轮谁说了什么、依据哪条证据" |
| **模型调用不用 SDK** | requests 直连 + 硬超时 | 商用 SDK 曾出现 SSL 握手无限阻塞，导致会话挂死；直连可精确控制超时与重试语义 |
| **检索排序全机械**，不用 LLM 判相关性 | 字面 + 实体约束 + 来源权威度 | LLM 判相关性不稳定（实测同批文献一次全留、一次全删）；机械排序**同输入同输出**，可复算 |
| **默认不部署向量库** | 检索走多源在线 | 实测嵌入模型无法区分"小学"与"师范生"（余弦差 ≈ 0.0001）——**学段是实体约束，不是语义倾向**；向量库在该场景收益低、依赖重 |
| **单进程 + 线程池**，不做微服务 | 单体部署 | 服务规模小（单机、低并发），微服务引入的分布式复杂度远大于其收益；故障面小、部署简单 |
| **会话全量落盘** | JSON/JSONL | 支撑"刷新/重启可重放"与"167 项数字可复算"两项承诺 |

## 五、与同类系统的架构差异

| 维度 | 通用对话式 Agent | 多 Agent 辩论框架 | **群智** |
|---|---|---|---|
| 异构来源 | — | 多为**同一 prompt 的角色扮演** | **认知原型 × 专业 × 价值**三层正交配置 |
| 信息分配 | 全员同一上下文 | 多为全员共享 | **受控不对称分配**（成员间 + 人机两层盲区） |
| 过程控制 | 无 | 固定轮次 | **基于可计算信号的条件干预** |
| 评审 | 无 / 单次打分 | 常缺 | **插件化 + 锚点自检 + 证据强制** |
| 证据链 | 无 | 无 | **代码生成 `[Pk]` + 三类核验** |
| 可审计性 | 黑盒 | 部分 | **全量落盘、逐轮信号可复现** |

## 六、术语表（本文用词与出处）

| 术语 | 英文 | 含义 |
|---|---|---|
| 多智能体系统 | Multi-Agent System (MAS) | 多个自主智能体通过交互完成共同任务的系统 |
| 认知异构 | Cognitive Heterogeneity | 成员在信息加工方式上的系统性差异（非随机扰动） |
| 角色配置 | Role Configuration | 智能体三元组 $(\pi, d, v)$ 的实例化 |
| 信息不对称 | Information Asymmetry | 成员掌握的私有信息集不相等 |
| 编排 | Orchestration | 对多智能体交互顺序、上下文与干预的统一调度 |
| 干预策略 | Intervention Policy | 由客观信号触发的条件动作函数 |
| 检索增强 | Retrieval-Augmented Generation (RAG) | 生成前注入外部证据 |
| 判定契约 | Judgment Contract | 评审输出的统一结构化 schema |
| 证据链 | Evidence Chain | 从证据注入到正文引用标记的可追溯路径 |
| 可观测性 | Observability | 系统内部状态（轮次、信号、干预）可被外部检查 |
