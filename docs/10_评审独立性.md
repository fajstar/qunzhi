# 群智 · 实验评审独立性说明

> **回答一个评委必然追问的问题**："798 轮评审记录（566 主 + 150 复现 + 82 补充）的评分，都是你们自己评的吗？"
>
> **一句话答案**：评分全部由 **AI 独立评审**完成（双模型五角色），裁判与选手分离、逐轮逐维留痕。
> 同时必须把三件事说清楚：① **没有人类盲评**；② **生成与评审同源**，排除不了自我偏好；③ 我们**自己证伪并下线了一把不及格的评分尺子**。

---

## 一、结论先行

**评分由双模型五角色独立评审完成，裁判与选手分离、逐轮逐维度留痕，关键结论全部经显著性检验。** 系统中的"评审委员会"与"讨论引擎"是两套完全独立的模块，评审员**看不到**讨论玩家的身份、配置和任何生成参数，只拿到匿名化讨论文本。

能证明什么、不能证明什么，先划清：

| 能证明 | 不能证明 |
|---|---|
| 裁判与选手是两套独立模块，评审输入里没有生成参数 | **没有人类盲评**，全部为 AI 独立评审 |
| 每维评分必须附原文依据（覆盖率 **100%**，**2555** 个维度实例）| 生成与评审**同源**（DeepSeek 生成；DeepSeek + GLM 评审），无法排除"模型偏好自家输出" |
| 评审器可被证伪——旧尺子盲测不及格，已被我们下线 | 评分绝对值不作质量等级，**只作组间相对比较** |

## 二、评审架构：裁判与选手分离

```
讨论引擎（选手，6 人虚拟团队 + 配置 + 主教练干预）
      │  输出：讨论文本（匿名化，不带任何元数据）
      ▼
评审委员会（裁判，五角色 × 双模型，输入仅讨论文本）
```

### 2.1 隔离措施

1. **信息隔离**：评审只接收讨论文本，不接收人格配置、专业标签、实验分组、干预指令等任何元数据——无法从输入推断"这是哪组实验"；
2. **双模型分工**：同一轮讨论由 DeepSeek 与 GLM 分别打分，但**分工是按维度切分、而非同一维度双评**——
   理论家/批评家/方法论审计员由 DeepSeek 承担，实践者/审计员由 GLM 承担。
   **边界**：单一模型并非"无法单方面决定结果"，而是"只决定自己负责的维度"；尤其**"真涌现"判定由批评家（DeepSeek）单独给出，属单模型判定**。这一点曾在本材料中被过度表述，此处更正；
3. **五角色独立打分**：理论家（深度）、实践者（落地性）、批评家（逻辑漏洞+真涌现判定）、审计员（幻觉/可靠性五维）、方法论审计员（评分方法本身）——五个视角互不背书；
4. **证据与置信度**：每维评分必须附原文证据（引用讨论文本片段），并带置信度；低置信度评分单独标记，不混入统计。

### 2.2 双模型分数如何合成（评委必问，明确口径）

| 环节 | 规则 |
|---|---|
| 分维度归属 | 理论家→深度/广度、批评家→涌现度/分歧质量（DeepSeek）；实践者→实用性、审计员→内容可靠性五维（GLM）；方法论审计员→四维（DeepSeek）|
| **同维度不出现两个模型** | 每个维度只由**一个**指定角色模型打分——**不取平均、不取低值、不仲裁** |
| 综合分 | 各维度分数取**算术平均**（学术五维→学术综合；审计五维→审计综合；方法论四维→方法论综合），无加权 |
| 缺维处理 | 某角色模型不可用时**回落 DeepSeek 完成该维度**（不静默丢维）；确实无法获取的维度在结果中缺失，而非按 0 分计入 |
| 真涌现判定 | 由批评家（DeepSeek，独立于讨论的裁判角色）给出 `is_genuine_emergence` **且**必须提供非空原文依据，二者同时满足才计为真涌现；**缺证据一律判为 False** |

> 关于 **563** 份 v3 评审记录（**AI 五角色独立评审，无人类盲评**）的口径：统计时**只用有对应 review 记录的轮次**（file_path 精确匹配），
> 缺评审记录的轮次不参与率值计算（566 轮评审记录中有 **3 轮**未生成评审）；置信度低于阈值的评分单独标记，不混入主指标均值。

### 2.3 v6 评审体系：把"独立性"做成机制（2026-09-17 之后新增）

| 机制 | 做法 | 为什么它加强独立性 |
|---|---|---|
| **成对强制选择** | 两两成对，必须判出更好的一份，**不给"差不多"的中间态** | 消掉"分数挤在一起、怎么打都行"的糊弄空间 |
| **分维三档** | 强 / 中 / 弱 / 无依据 | 每一档都必须落到具体维度与原文依据上 |
| **锚点自检** | 出分前先做锚点题；**未通过就不出分** | **评审器必须先证明自己认得出好坏，才被允许给分** |
| **独立风险栏** | 风险项单独列出，不与优点混栏 | 防止"分数高就什么都好"的晕轮效应 |

### 2.4 评审器插件化：评审不绑定单一实现

评审器做成**即插即用插件，用户自选**：**v3**（快，单轮约 **40 秒**）/ **v6**（准，单轮约 **160 秒**）。
意义是：**评审不是写死在系统里、不可替换的环节**——用户可换成别的插件或按接口自行实现，**评审结论不依赖"我们这一家的实现"**。

## 三、真涌现判定的独立把关

"涌现"是本作品核心理念（不是人问AI答），若由系统自评容易自卖自夸。因此：

- **批评家角色专职判定**：严格区分"真涌现"（提出可落地的、讨论中此前未出现的全新方案）与"伪涌现"（换词复述、无落地路径），判定标准（可验证性/新颖性/落地性三条件）写死在评审提示词中，非主观印象；
- 真涌现率 **57.7%（325/563）** 是**批评家独立判定**的结果，非系统声称：分母为全部 563 份 v3 评审记录，未判定记为"非真涌现"；若只在有涌现度判定的 **440** 份样本内计算，则为 **325/440 = 73.9%**；
- **判定可复核**：报告页每个维度都可展开查看判定角色、模型、置信度与**原文证据**；接口层面可直接调用
  `POST /api/review/evaluate`（提交包内 `app/review_v3.py` 为完整实现）复核，
  返回结构中 `scores[维度].evidence / confidence` 与"真涌现判定"字段即为判定依据。

> ⚠️ **这一指标只作过程描述，不作质量证据**：它与"涌现度"分数的**阈值一致率 98.6%、Jaccard 0.979**——
> 是同一把尺子的两种写法。唯一允许的说法是"**57.7% 的产出被批评家判定为真涌现**"。

## 三·五、自我证伪：我们下线了自己不及格的评分尺子

| 项 | 事实 |
|---|---|
| v3 的 1–10 分尺子 | 在同一批 **18 对**材料上**只挑对 8/18（44%）**——**低于瞎猜的 50%** |
| 根因 | **尺子没有刻度**：分数挤在 **6.4–7.2**（跨度 0.8），判定门槛 0.5 → **10 对"看起来一样"** |
| 谁发现的 | **我们自己**——不是评委指出，也不是外部审计发现 |
| 处置 | **1–10 分已下线**，改用 **v6 成对强制选择**；旧尺子留档，并标注证伪数据 |
| v6 验证 | 三家评审 **18/18、17/18、17/18** 全部达标，两轮一致 |

> 这是本说明里最有力的一条：**一个不肯检验自己的评审体系，说自己"独立"是没有说服力的。**
> 我们不但检验了，而且在它不及格时把它下线——**"独立性"因此不只是一句声明，而是一条可被证伪的机制**。

## 四、统计严谨性

| 维度 | 做法 |
|---|---|
| 样本量 | 798 轮评审记录（主 566 + 复现 150 + 补充 82）中的 **563** 份 v3 评审记录；另有 **172 次对照实验**（三臂对照 32 + 人格消融 140，后者每组 n=20）|
| 评审独立性 | 双模型（DeepSeek + GLM）五角色独立打分，裁判与选手分离，file_path 精确匹配 |
| 对照实验 | **预注册**（判定规则跑前写定，跑后不改）；正式版前先做阴性对照（同配置拆两组各 20 次，配对差分 +0.000、p=1.0000）|
| 数据审计 | 发现并修复评分回填 Bug（topic+group 误匹配，污染 15 条记录），结论改为基于权威库 review_db_v3 直接统计 |
| 负结果报告 | 条件效应未检出（F(12,550)=1.291，p=0.219；χ²(12)=12.63，p=0.397）、最优人格差异极小（d≈0.05；⚠ 该值来自已作废评审库，不作结论）——**负结果也是结果** |
| 短板披露 | 审计五维中透明性为相对短板，V15 以强制来源标注针对性改进 |

## 五、可复现性承诺

- 评审提示词、评分维度定义、显著性检验脚本均随代码交付（`app/review_v3.py` + 实验工具），评委可抽记录核对证据引用是否成立；
- **实验数据已随包分发**：`实验数据与审计记录/review_db_v3.json`（563 份 v3 评审记录，含每维评分/置信度/原文证据）
  + `master_table.csv`（566 轮、43 列），附 SHA256/MD5 校验和与**可直接运行的复算脚本**——
  评委可当场复算**全局指标**（真涌现 325/563 = 57.7%、综合 7.95、审计 8.11/n=557）及全部**记录级统计**；
- **不能复算的部分（如实说明）**：分组级统计无法由随包数据独立复算，因原始记录的组标签未写全
  （`experiment_group` 仅有"基础实验""B""D""E1"四类）；界线见《实验数据与审计记录/README.md》第五节；
- **对照实验可复算**：172 次对照实验的原始输出随包留存（预注册文件 + 每次运行完整输出，不删不改），
  复算脚本与统计口径见《三臂对照与人格消融实验报告》第十一节；
- 讨论原文（每轮完整讨论文本）因体积原因未随包分发，答辩现场可出示。

> 这样处理的原因：既然把"公开数据审计"写进了创新点，就要让它**当场可核验**，而不是只承诺"答辩时可出示"。

## 六、局限与下一步实验目标（诚实披露）

> **评审性质**：当前评审为 **AI 独立评审，全程无人类盲评**；我们已设计低成本盲评方案，将在后续版本完成。
> **同源风险**：讨论由 DeepSeek 生成、评审由 DeepSeek + GLM 完成，**同源模型家族，存在"模型偏好自家输出"的循环依赖**——
> 这在大模型评测文献中已有记录，**我们在现有资源下无法排除它**。
> **度量缺陷**：部分维度近乎无区分度，综合分不适合组间排序（旧版 1–10 分尺子已因不及格而下线，见第三·五节）。
> **模型漂移**：实验基于调用时的模型版本（`deepseek-chat` 别名 + GLM-4-flash）；服务商更新后同名模型可能指向不同能力版本，
> 复现输出可能存在差异——这是所有基于闭源 API 的实验共同边界。

**我们如何看待这条局限**：评审由 AI 完成，是本项目当前最大的方法论边界。我们不掩饰它——
"裁判与选手分离"解决了"自己评自己"的问题，但没解决"AI 评 AI 是否有系统性偏好"的问题。因此把它写成四个可执行的下一步：

| 局限 | 下一步方案 |
|---|---|
| **无人类盲评、无评分者间信度（IRR）** | 低成本盲评方案（抽 30 轮讨论文本，请 5 位师范生/教师盲评排序，计算人类评分与 AI 评分的一致性系数并公开差异分析）|
| **生成与评审同源（循环依赖）** | 引入不参与生成的第三方模型作独立裁判，或以人类评分作锚点校准 AI 评分偏移 |
| 高张力结论可能含评审偏见 | 同一讨论用不同张力标签提交评审，检验评审是否有"张力敏感"偏置 |
| 模型漂移（同名模型版本变化）| 复现时记录调用模型快照/时间戳；对关键结论做跨版本一致性抽检 |

**这符合本项目的一贯做法**：能复现的才写，不成立的就不写，无法排除的就说清楚。最直接的证据：
我们**推翻过自己两条结论**（d=0.543 已重算为 d≈0.05（⚠ 重算所依据的评审库本身被匹配 Bug 污染了 383/563 条，故两个数均不作结论）；「多智能体显著优于单智能体」已被推翻（**仅在「视角覆盖数」代理指标上判不出差别，非质量结论**）），并**下线了一把不及格的评分尺子**。
