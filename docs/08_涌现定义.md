# 「涌现」与「涌现率」：定义与计算方法

> **用途**：直接回应评审意见第 3 条——「'涌现'的概念不明晰，'涌现率'的计算方法不详」。
> **本文件给出一层不跳步的操作化链路**：概念定义 → 评分量表 → 布尔判定 → 比率计算 → **可复算验证** → 为什么不作质量证据。
> **可复算性**：本文所有数字都能用 `实验数据与审计记录/review_db_v3.json`（563 条评审记录）重算，脚本见第七节。

---

## 一、概念定义：本系统中的「涌现」是什么

### 1.1 一般定义（复杂系统 / 多智能体语境）

在多智能体系统（MAS）与复杂适应系统（CAS）研究中，「涌现」（emergence）指**系统整体表现出的、任何单个组分都无法独立产生的性质或行为**。判定涌现的关键不在"结果看起来复杂"，而在于**不可归约性**（irreducibility）：不能把整体输出拆解为各成员输出的并集。

### 1.2 本系统的操作化定义

我们把上面这个抽象定义落成一个可判定的操作条件：

> **涌现 = 讨论产出的方案，① 无法从注入的信息库直接推导，② 且具备具体实现路径。**

两条必须同时成立。只满足第一条（造了新词但落不了地）不算；只满足第二条（把信息库里现成方案抄一遍）也不算。

### 1.3 为什么必须区分「真涌现」与「伪涌现」

大模型有一个典型失效模式：**用新词冒充新思想**。「构建多维协同赋能体系」这种表述在字面上很新，但拆开看没有任何可执行内容。如果只按"是否包含新表述"来判涌现，这个指标会立刻失效——因为模型几乎总能造出新词。

所以我们在判定时强制区分：

| 类型 | 特征 | 判定 |
|---|---|---|
| **真涌现** | 提出信息库中完全没有的方案，且给出具体实现路径 | `is_genuine_emergence = true` |
| **伪涌现** | 提出新词，但没有实现路径 | `is_genuine_emergence = false` |
| **无涌现** | 未超出信息库已有内容的重新组织 | `is_genuine_emergence = false` |

## 二、谁来判定：角色与约束

涌现判定由评审体系中的**批评家（Critic）**角色承担。它是五角色评审中的一个独立角色，职责就是甄别创新真伪。

**角色配置**（取自 `app/review_v3.py` 的 `CRITIC_PROMPT`）：

| 项 | 设定 |
|---|---|
| 角色定位 | 「专门甄别创新真伪的评审专家（批评家）」 |
| 评审对象 | 单份预演报告正文 |
| 输出维度 | **涌现度**（1–10 分）、**分歧质量**（1–10 分） |
| 强制约束 | 每个维度必须给 **score + confidence（1–10）+ evidence（原文依据）** |
| 布尔判定 | 输出 `is_genuine_emergence: true / false` |
| 无证据处理 | **判「真涌现」必须附原文证据，否则记否** |

**这一点很关键**：涌现度不是自由打分。它被要求引用报告原文作为依据，且要另给一个置信度。也就是说每一条记录都包含**「分数 + 依据 + 置信度 + 布尔判定」**四元组，可逐条回溯。

**判定要点（原文摘录，即实际下发给模型的指令）**：

```
1. 涌现度：报告中是否产生了任何单一AI无法独立提出的、可落地的、能解决课题的新方案？
   - 高分要求：方案可运行、有具体实现路径，且无法从信息库直接推导
   - 低分标志：仅仅是换了一种说法，或提出无法落地的新词
关键区分：
   - "真涌现"：提出了信息库中完全没有的、可落地的方案
   - "伪涌现"：提出了新词，但没有具体实现路径
```

## 三、涌现度的计算：1–10 分是怎么来的

### 3.1 评分流程

```
预演报告正文 ──→ 批评家模型（DeepSeek）──→ JSON {
    "涌现度":   {"score": 1-10, "confidence": 1-10, "evidence": "原文片段", "is_genuine_emergence": bool},
    "分歧质量": {"score": 1-10, "confidence": 1-10, "evidence": "原文片段"}
}
```

- **模型**：`deepseek-chat`（与生成模型同族，所以我们在材料里如实披露了"评审与生成同源"这一限制）
- **温度**：低温度 + 严格 JSON 输出格式
- **输入**：报告全文（超长时截断）
- **输出**：严格 JSON，不接受自然语言评语

### 3.2 分数语义（锚点）

| 分数区间 | 语义 | 判定倾向 |
|---|---|---|
| 9–10 | 提出可运行方案 + 完整实现路径 + 无法从信息库推导 | 真涌现 |
| **7–8** | **提出可落地的新方案，路径基本完整** | **真涌现** |
| 5–6 | 有超出信息库的思路，但实现路径不完整 | 视证据，多数判否 |
| 3–4 | 主要是重新组织信息库内容 | 否 |
| 1–2 | 换成新说法但无实质内容 | 否 |

### 3.3 度量有效性的自检（这一步很多作品不会做）

我们检验了这把尺子的**区分能力**：用 18 对"已知好坏"的报告做 A/B 对比，看涌现度能否挑出更好的那份。

**结果：只挑对 8/18（44%），低于随机。** 同一批 18 对里，18 份报告的分数挤在 **6.4–7.2**，跨度仅 **0.8 分**。

**结论：涌现度这把尺子没有刻度。** 这不是"我们做得还行"，而是"这个维度在全批次上分辨不出差异"。这条结论我们写进了材料，也从不当优势讲。

## 四、真涌现率的计算：公式与两种分母

### 4.1 计算公式

$$
\text{真涌现率} = \frac{\#\{i : \text{is\_genuine\_emergence}_i = \text{true}\}}{\text{分母}}
$$

**分母有两种口径，必须分别报，不能混用**：

| 口径 | 分母定义 | 数值 | 适用 |
|---|---|---|---|
| **权威口径（全样本）** | 全部有效评审记录 | **325 / 563 = 57.7%** | 对外主口径 |
| **样本内口径** | 只算**有明确判定**的记录（剔除未判定的 123 份早期旧格式） | **325 / 440 = 73.9%** | 与各维度分数对比时用 |

### 4.2 为什么 563 里只有 440 条有判定

563 份有效评审中，**123 份是早期旧格式**，评审 prompt 只含「深度 / 广度 / 实用性」三个维度，**没有涌现度与真涌现判定**。

**这 123 份必须记为"未判定"，不能记为"非真涌现"**——把缺失当否定，会把真涌现率人为压低约 22 个百分点。这是我们在复算时踩过的坑，也是为什么两种口径要同时报。

### 4.3 「325」这个分子的来源

逐条统计 `scores["涌现度"]["is_genuine_emergence"] == true` 的记录数，无任何加权、无任何插补。

**复算方法**（可直接跑）：

```python
import json
d = json.load(open("实验数据与审计记录/review_db_v3.json", encoding="utf-8"))
reviews = d["reviews"]                      # 563 条
has = []
for r in reviews:
    em = (r.get("scores") or {}).get("涌现度")
    if isinstance(em, dict) and "is_genuine_emergence" in em:
        has.append(bool(em["is_genuine_emergence"]))
print(len(has), sum(has))                   # → 440 325
print(sum(has) / len(reviews))              # → 0.577  = 57.7%
print(sum(has) / len(has))                  # → 0.739  = 73.9%
```

## 五、关键验证：真涌现率与涌现度评分的关系

这一节是评审最可能追问的地方：**「真涌现率」是不是独立的第二个指标？**

**不是。我们实测验证了它其实是涌现度评分的一个阈值化写法。**

### 5.1 阈值的反推

对 440 条有判定的记录，逐一比较「涌现度 ≥ T」与「is_genuine_emergence」，扫不同阈值：

| 阈值 T | 一致率 | Jaccard |
|---|---|---|
| score ≥ 5 | 74.1% | 0.740 |
| score ≥ 6 | 74.3% | 0.742 |
| **score ≥ 7** | **98.6%** | **0.982** |
| score ≥ 8 | 26.4% | 0.003 |
| score ≥ 9 | 26.1% | 0.000 |

**结论：`is_genuine_emergence` 实质上等价于「涌现度 ≥ 7」。一致率 98.6%，Jaccard 0.982。**

> **口径差异如实说明**：早期材料写的是「Jaccard 0.979」，本次复算得 0.982，差 0.003。差异来自集合定义（本次用 `|交集| / |并集|` 直接计算；早期脚本的分子分母口径略有不同）。**一致率 98.6% 两处完全一致，主体结论不受影响。** 我们保留两个数字并标注来源，不强行统一。

### 5.2 这意味着什么

既然 `真涌现率 ≡ P(涌现度 ≥ 7)`，那么：

- **用真涌现率证明"产出质量高"是循环论证**——它只是同一个分数换了种写法；
- 而我们已经验证**这把尺子本身没有刻度**（第 3.3 节，18 对照只挑对 8 对，分数挤在 6.4–7.2）。

**两条加起来 → 真涌现率不能作为质量证据。**

所以我们在全部对外材料里把它降级为**过程指标**，标准表述为：

> 「**57.7% 的产出被批评家判定为真涌现**（过程指标，不作质量证据）」

**而不是**「真涌现率 57.7%，证明质量高」。

## 六、这个指标的适用边界（明确写清，避免误用）

| 可以这么说 | 不能这么说 |
|---|---|
| 57.7% 的产出被批评家判定为真涌现 | 真涌现率 57.7% 说明产出质量高 |
| 这是评审模型给出的过程判定 | 这是人工盲评的结论 |
| 判定附原文证据与置信度，可逐条回溯 | 这个数字与"涌现度"分是独立的两把尺子 |
| 全样本 57.7%、样本内 73.9%，两种口径同时报 | 只报 73.9%（会显得更好看，但口径不完整） |
| 该指标在不同实验组间存在 35.0%–67.5% 的波动 | 组间差异反映实验条件效应（**χ²(12)=12.63，p=0.397，不显著**） |

**另外两条必须披露的噪声**：
- 同一条件的记录按时间对半拆开，两半的真涌现率差 **平均 11.7 个百分点、最大 28.6 个百分点**——报告噪声本身就大于多数组间差异。
- 判定准确度受**评审与生成同源**限制（均为 DeepSeek 系），所以我们同时保留了三家独立模型（MiniMax / GLM / Qwen）的 v6 评审作为交叉验证。

## 八、结论（一段话）

> 在本系统中，**涌现**被操作化为「讨论产出了信息库中无法直接推导、且具备具体实现路径的新方案」；由批评家角色对每份报告给出 **涌现度 1–10 分 + 原文依据 + 置信度 + 真涌现布尔判定**；**真涌现率** = 判定为真的份数 / 有效评审份数 = **325/563 = 57.7%**（样本内 325/440 = 73.9%）。
>
> 但我们必须同时说明：**该布尔判定与「涌现度 ≥ 7」的一致率达 98.6%（Jaccard 0.982），是同一个分数的阈值化写法，不是独立指标**；而这把尺子经 18 对照测试**只挑对 8 对（44%）**，缺乏分辨力。**因此我们不把真涌现率作为质量证据，仅作过程描述。**
