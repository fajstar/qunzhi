## 一、口径更正（最重要）

### 1.1 删除「18.5 倍成本差」这一结论

**原表述**：「A 臂 45,074 token，C 臂 2,437 token，**成本差 18.5 倍**」

**问题**：18.5 = 45,074 ÷ 2,437，比的是**不同工作量**：

| | A 臂（6 人团队） | C 臂（单模型多视角） |
|---|---|---|
| 调用次数 | 37 次 | 1 次 |
| 检索注入 | ✅ | ❌ |
| 6 角色 × 3 轮讨论 | ✅ | ❌ |
| 主教练逐轮干预 | ✅ | ❌ |
| 报告生成 | ✅ | ✅ |
| 审计意见 | ✅ | ❌ |
| 涌现分析 | ✅ | ❌ |
| 参考文献 | ✅ | ❌ |

**更根本的问题**：我们只测了「视角覆盖数」（关键词计数），**内容价值从未被评估**。
价值没测，任何「贵/便宜 X 倍」都无依据。

**已改为**：全部材料里的「成本比 / 成本差 18.5 倍」→ **「token 比 18.5 倍」**，
并注明「两者工作量不同，不是等价产出的成本比较」。共修正 **25 处 / 9 个文件**。

**同时删除**：推算出的「约 6 倍」（拿 A 臂最后 4 次调用凑成「报告成本」，同样是硬拆）。

### 1.2 PPT P9 / P11 同步修正

| 页 | 原内容 | 现内容 |
|---|---|---|
| P9 | 「单 AI 的成本是我们的 1/18.5」 | 「覆盖度上 TOST 判定等价；但**内容价值我们从未评估** —— 这个对照既不能证明我们更好，也不能证明更差」 |

## 二、代码修复（线上，staging）

### 2.1 arXiv 检索修复（4 处）

| # | 问题 | 修复 |
|---|---|---|
| ①-A | 中文课题无法映射英文时，**原样把中文发给 arXiv** → TLS 握手超时 106 秒 | `zh_to_en_query` 无法映射时返回空串，`tech_search` 见空跳过 arXiv |
| ①-B | 中英词表只有 47 个词，全为计算机方向，「变换器」「纹波」等未覆盖 | 扩充至 **207 词**，覆盖电力电子/控制/机械/材料/化学/生医/土木 |
| ①-C | `timeout=30 × retries=3`，而总熔断只有 10s → 重试未完成即被熔断 | 改为 `timeout=15, retries=1` |
| ②-B | Semantic Scholar 无 API key 时 429，仍白等一次退避 | 无 key 只试 1 次 |

**实测效果**：

| 课题 | 修复前 | 修复后 |
|---|---|---|
| Buck 变换器（中文科研题） | 106.8s 超时，**0 篇** | **3.19s，命中 10 篇** |
| 分布式缓存 | 43.7s，0–5 篇 | **2.86s，10 篇** |
| 师范生课堂参与度 | 1.6s，0 篇 | 正确跳过 arXiv（3.3s，OpenAlex 兜底 5 篇）|

### 2.2 `force_dynamic_info` 接线 + 报告标注

**原问题**：`force_dynamic_info` 是**死参数** —— 只在 `__init__` 签名里出现，全文从未被使用。
导致检索失败时**直接退回通用预置库**（与课题无关），动态生成永远走不到。

**修复**：接上新分支，并区分优先级：

```
① custom_infos（检索成功，带 [P#] 编号）        → 最高
② 专属预设（6 段中 ≥3 段带「来源」，人工整理）    → 次高
③ force_dynamic_info 且无专属预设               → 按课题现编 + 报告标注
```

**注意**：初版修复把 ③ 放在 ② 之前，会让 **17 个「_真实」专属预设失效**
（如 `分布式缓存系统_真实` 含 Redis 官方文档、`AI代写作业_真实` 含 Turnitin 2023）。
已修正为专属预设优先。

**报告标注**：走现编路径时，报告末尾追加：

```
⚠ 背景信息为推断生成（非检索结果）
本次 6 位角色的背景资料由模型按课题推断生成，不是检索到的真实文献。
- 文中不带 [P#] 编号的具体数字、报告名、机构案例，均需自行核实
- 标注「待验证」的内容没有外部依据
- 需要可核验来源时，请检查检索是否成功（source_status）
```

### 2.3 `call_with_retry` 增加截断告警

**原问题**：只判断内容是否为空，**从不检查 `finish_reason`**。
推理型模型（如 GLM-5.x）把 `max_tokens` 全花在 reasoning 上，content 为空、
`finish_reason=length`，系统静默重试后返回 None，日志里看不出根因。

**修复**：空内容时检查 `finish_reason`，为 `length` 则打明确告警并提示所需 token 数。
