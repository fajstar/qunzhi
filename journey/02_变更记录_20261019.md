## 一、检索层：从"单一知网"到"12 源并行 + 机械排序"

### 1.1 发现：所谓"12 源"实际只有知网在工作

**证据（改前实测，4 个课题）**：

```
教研-A   逐源: cnki=8
教研-B   逐源: cnki=8
社科-D   逐源: cnki=8
非教育-C 逐源: cnki=8
```

**根因（代码位置）**：

```
coach_search.py:736   if len(cleaned) >= 3: return {...}   ← 知网 ≥3 条直接返回
coach_search.py:808   multi_source_search(...)             ← 多源检索在其后，永不执行
```

知网对中文课题几乎总能拿到 ≥3 条 → 永远早退 → **其余 11 个源从未被调用**。

**处置**：新建 `app/retrieval_v2.py`，改为并行抓取全部源；旧链路保留为回退（`QUNZHI_RETRIEVAL=v1` 可整体切回）。

### 1.2 新链路（四阶段，全程不用 LLM 判相关性）

```
① 并行抓取   12 源 × 每源 8~10 条，总超时 10s 熔断，超时的源标 timeout
② 机械去重   题名归一优先（去标点/全半角/空格）+ DOI 兜底，保留信息更全的
③ 机械打分   见 1.3
④ 多样性选取 top-k，每源 ≤4 条，网络源 ≤1 条，低质文库直接剔
```

**为什么不用 LLM 判相关性**：实测 `_judge_relevance` 在非教育课题上把 10 条国际源**全判不相关**（返回 NONE），池子直接塌成 0；换课题又可能过度宽松。机械打分是确定性的：同样输入永远同样输出，能解释、能复算。

**效果**：

| 课题 | 改前 | 改后 |
|---|---|---|
| 教研-A | 8 条 / 0.398 / **1 源** / ~10s | 5 条 / **5/5 相关** / **5 源** / 7.2s |
| 教研-B | 8 条 / 0.385 / 1 源 | 8 条 / **8/8** / **6 源** / 9.4s |
| 非教育-C | 5 条 / 0.014 / 1 源 | 5 条 / **5/5** / **4 源** / 6.4s |
| 社科-D | 8 条 / 0.260 / 1 源 | 8 条 / **8/8** / **6 源** / 8.2s |

> 相关性 = 标题与「课题 + LLM 拆出的检索词」的最大字面重合度，≥0.15 记为相关。

### 1.3 打分公式（全部机械，零模型）

```
最终分 = 绝对分 × 权威度^0.35 × 完整度门 × 语言因子

绝对分   = 0.32×题名重合 + 0.22×摘要重合 + 0.09×期刊层级
         + 0.22×摘要完整 + 0.10×来源可信度 + 实体约束
完整度门 = 0.45 + 0.55×完整度        （无摘要 ×0.45）
语言因子 = 1.06（中文）/ 0.88（英文，仅中文课题启用）
```

| 成分 | 作用 | 实测依据 |
|---|---|---|
| **权威度乘法门** | 挡"低权威源"（网络文库、无来源） | bocha《学周刊》2014 权威度 0.18，改前排第 2，改后被压出 Top-8 |
| **实体约束**（学段/受众） | 区分「师范生」与「小学/中职」 | 师范类 0.393 vs 小学类 0.063（差 6 倍） |
| **泛词排除** | 挡「提升策略」「优化路径」类假匹配 | 「大学生健康体适能…提升策略」字面分 0.117 → **-0.050** |
| **完整度门** | 挡"只有题录、没有正文" | 摘要覆盖率 1/5 → 6/8 |
| **语言因子** | 中文课题优先中文文献 | 英文文献 1/5 → 0~1/8 |

### 1.4 为什么"语义相似度"没有用来排序

已接入 DashScope `text-embedding-v3`（1024 维，**无需任何本地依赖**，不装 chromadb/torch），但实测结论是**只能过滤、不能排序**：

**它做得好的** — 语义分最低的确实是真垃圾：
```
0.343 跨文化语用学视角下外宣翻译策略分析
0.333 APTox: Assessment and Prediction on Toxicity
0.264 Petrogenesis of the highly fractionated granites
```

**它做不好的** — 语义分最高的常是"抄课题原话"的低质文库：
```
0.758 教师培训资料分享:提高学生课堂参与度的策略.docx_咨信网
0.737 增强学生参与度的教学策略与技巧.pptx-原创力文档
0.721 高职院校师范生课堂教学能力培养探析   ← 这条才是对的
```

**更关键**：「医工交叉领域技术转移转化能力提升高级研修班」（真对口）语义分只有 **0.337**，而「天津科技局工作动态」0.611 排第一。

**原因**：垃圾文档抄的就是课题原话，语义自然最近；真文献用自己的术语体系表述。

**处置**：语义**只作过滤**（cos < 0.32 丢弃），**不参与打分**；默认关闭（`QUNZHI_SEMANTIC=1` 开启，+2~3s）。

### 1.5 实测过的、被否决的社区做法

**RRF（Reciprocal Rank Fusion）— 实现后否决。**

RRF 是社区多源融合的标准做法（Cormack et al. SIGIR 2009, k=60），但它有个隐含前提：**各源的内部排序质量可比**。我们这里不成立：

| 源 | 内部排序是什么 |
|---|---|
| 知网 | 真实检索相关度（好用） |
| **Crossref** | **模糊匹配顺序**，第 1 名常是字面最像的无关论文 |
| ncpssd | 类似 |

给 RRF 0.55 权重后，教研课题 Top-8 又变回「小学语文/小学数学」，非教育课题冒出「新型冠状病毒肺炎」「高龄不良孕产史」。

**处置**：RRF 默认关闭（`QUNZHI_RRF=1` 可开做对比），代码保留在 `app/retrieval_fusion.py`。

**MMR（Maximal Marginal Relevance）— 保留。** 用于多样性重排，`λ=0.62`，相似度用题名 bigram Jaccard。

## 二、信息密度：每玩家 300 字 → 1000 字

### 2.1 发现

```
citations.py:326  render_injection(pool, index, own_span=150, shared_span=80)
                  body = (rec.get("abstract") or rec.get("content") or "")[:span]
```

而摘要本身 237–400 字 → **只给了一半**。

**更糟**：新写的 v2 没有构建 `content` 字段（0 字），而 8 条里 5 条是知网题录（21–53 字无摘要）→ `body` 为空 → 玩家看到的是：

```
[P6]（学术）高师地理师范生课堂教学能力提升策略（教育研究, 2024）：
                                                                    ↑ 空白
```

### 2.2 改法

| 项 | 改前 | 改后 |
|---|---|---|
| `own_span` / `shared_span` | 150 / 80 | **420 / 220** |
| 每玩家看到文献数 | 2 条 | **3–4 条** |
| v2 是否构建 `content` | ❌ 0 字 | ✅ 235–600 字 |
| 摘要完整度权重 | 0.05 | **0.22** + 乘法门 |
| 空摘要条目标注 | 无 | 「本条仅题录，无摘要 —— 不要据此陈述结论」 |
| 分配轮转 | 小池子会漏人 | 加全局记账表，优先未分配条目 |

### 2.3 效果

| 指标 | 改前 | 改后 |
|---|---|---|
| 每玩家注入字数 | 286–384 字 | **844–1153 字** |
| 每玩家看到篇数 | 2 篇 | **3–4 篇** |
| 摘要覆盖率 | 1/5 ~ 4/8 | **5/5 ~ 6/8** |
| 覆盖利用率 | 6/7 = 86% | **5/5 或 8/8 = 100%** |

> 「信息利用率」可达 245–281%，因为同一篇被 2–4 个玩家看到 —— 这是**刻意的不对称注入**，不是浪费：不同玩家从同一篇文献读到不同角度，才能形成信息差。

## 三、摘要抓取器：修好两个连环 bug

### 3.1 Bug 1 — URL 闸门把可用页面全拒了

```python
def fetch_abstract(url, ...):
    if not url or "abstract" not in url:
        return None          # ← cnki.com.cn/Article/*.htm 全部被拒
```

### 3.2 Bug 2 — cookie 路径少查一层（真正的杀手）

```
BASE = app/rag
候选: app/cookies/cnki.json          ← 不存在
      app/rag/cookies/cnki.json      ← 不存在
实际: /home/ubuntu/qunzhi-staging/cookies/cnki.json   ← 项目根
→ 读不到 cookie → fetch_abstract 直接 return None
```

**所以之前所有 URL 都返回 None，不是抓取逻辑的问题，是 cookie 找不到。**

### 3.3 修完实测

```
cnki.com.cn/Article/*.htm   → 130 字 ✓
cnki.com.cn/Article/*.html  → 130 字 ✓（自动改写 .htm，.html 是登录墙）
doi.org/...                 → None ✓（正确拒绝，不浪费时间）
ncpssd.org                  → None ✓（正确拒绝）
```

### 3.4 已知限制（必须如实说明）

**池子里 URL 的域名分布（实测）**：
```
doi.org:     3 条   ← 抓不到（DOI 解析到 chndoi.org/Resolution/Handler 空壳页）
cnki.com.cn: 1 条   ← 能抓
ncpssd:      1 条   ← 本来就有摘要
```

**只有约 20% 的条目 URL 可抓。** 知网文献的 URL 大多是 DOI 链接，而 CNKI DOI 无法反推 `CJFDTOTAL-xxx` 编号。

**结论：摘要覆盖率做不到稳定 100%**，会继续在 5/5 ~ 6/8 之间浮动，取决于这一轮检索命中什么。

**已尝试但否决的方案**：直接剔除无摘要条目 —— 实测 5 条里只剩 1 条相关，因为**对口的中文文献恰恰大多是知网题录（无摘要）**，而有长摘要的多是 ncpssd 的泛化论文与 bocha 文库。

## 四、稳定性：30 秒 → 7 秒

### 4.1 发现

教研-A 偶发 33.8s。拆解时间后发现不是网络抖动：

```
retrieve 总 7.1s → 但只产出 2 条（原始 50 条候选）
search_topic 24.5s → source=multi   ← 回退到 v1 老链路
```

**根因**：相对阈值 `0.50 × 最高分` 在分差压缩时砍太狠（50 条 → 2 条），触发 `<3 条回退 v1`，v1 链路 = 知网串行 + 博查 + 多源 = 24.5s。

### 4.2 处置

- 总超时 18s → **10s**
- 新增**数量下限保护**：阈值过滤后不足 5 条 → 按分数取前 5 条

### 4.3 效果

```
修前: retrieve 只出 2 条 → 回退 v1 → 24.5s
修后: retrieve 出 5 条 → 走 v2 → 4.2s
```

**耗时 24.5s → 4.2s，快 6 倍。**
