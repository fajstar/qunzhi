## 三、核心指标复算（可直接运行）

> 本节脚本可复算**记录级**的全部指标。**组级**指标（10 个实验组的 n / 综合分 / 真涌现率）
> **无法由本目录复算**，原因见第五节。

```python
import json
d = json.load(open("review_db_v3.json", encoding="utf-8"))
recs = d["reviews"]

def truthy(v):
    if v is True: return True
    if isinstance(v, str): return v.strip().lower() in ("true", "yes", "1", "是")
    return False

def emergence(r):
    for k in ("真涌现", "is_genuine_emergence"):
        if k in r: return r[k]
    return ((r.get("scores") or {}).get("涌现度") or {}).get("is_genuine_emergence")

flags = [emergence(r) for r in recs]
n_true = sum(1 for f in flags if truthy(f))
n_false = sum(1 for f in flags if str(f) == "False")
n_none = sum(1 for f in flags if f is None)

def avg(key):
    v = [r.get(key) for r in recs if isinstance(r.get(key), (int, float))]
    return len(v), round(sum(v) / len(v), 2) if v else None

print("评审记录数:", len(recs))                                  # 563
print("真涌现 True/False/未判定:", n_true, n_false, n_none)      # 325 115 123
print("真涌现率(全部563为分母):", round(100*n_true/len(recs), 1), "%")   # 57.7
print("真涌现率(有判定的440内):", round(100*n_true/(n_true+n_false), 1), "%")  # 73.9
print("综合评分:", avg("综合评分"))          # (563, 7.95)
print("审计综合:", avg("审计综合评分"))      # (557, 8.11)
print("方法论综合:", avg("方法论综合评分"))  # (563, 4.59)
em = [r["scores"]["涌现度"]["score"] for r in recs
      if isinstance((r.get("scores") or {}).get("涌现度", {}).get("score"), (int, float))]
print("涌现度维度:", len(em), round(sum(em)/len(em), 2))         # 440 6.73
```

**预期输出**（2026-09-12 实测复算）：

| 指标 | 结果 | 说明 |
|---|---|---|
| 评审记录数 | **563** | 566 轮主实验中有 3 轮未生成评审记录（评审调用失败/未执行），故率值一律以 563 为分母 |
| 真涌现 True / False / 未判定 | **325 / 115 / 123** | 123 份为 V14 时期旧格式评审，未包含涌现度维度 |
| 真涌现率（全部 563 为分母） | **57.7%** | 未判定记为"非真涌现" |
| 真涌现率（有判定的 440 份内） | **73.9%** | 两个口径都公开，避免被误读为置信区间 |
| 综合评分 | **7.95**（n=563） | 学术五维算术平均 |

| 涌现度维度均值 | **6.73**（n=440） | 由 v1 的 8.83 自纠下调 24% 后的严谨标准 |

## 五、可复算范围（重要，请先读这一节）

本目录提供的是**记录级**数据。它能复算什么、不能复算什么，界线如下：

| 类别 | 具体内容 | 能否由本目录复算 |
|---|---|---|
| 记录级统计 | 记录数 563、各维度均值/标准差/取值分布、证据覆盖率、维度间相关 | ✅ 能（见第三节脚本） |
| 真涌现率 | 325/563 = 57.7%；有判定样本内 325/440 = 73.9% | ✅ 能 |
| 综合指标 | 综合分 7.95、审计综合 8.11（n=557）、涌现度 6.73（n=440）、方法论四维 4.59 | ✅ 能 |
| 按记录条件分组 | 用 `condition` 字段（含人格/信息/干预三要素）分组做方差分析或卡方检验 | ✅ 能（该字段完整） |
| **10 个实验组的组级统计** | 各组 n、综合分、真涌现率（如 V15-C 35.0%、V14基础 62.4%） | ❌ **不能** |

**为什么组级统计不能复算**：这些组的归属来自实验实施方的内部汇总表。原始记录中
`experiment_group` 只写入了「基础实验」「B」「D」「E1」四类，A、C、E2、E3、E4、F 等组**没有标签**，
且已标注的 B/D/E1 也不完整（例如 B 在汇总表中 n=40，原始记录中只有 32 条带标签）。
因此按组筛选会得到残缺甚至错误的分组，**请勿据此复算组级数字**。

这是一个已知的工程疏漏：实验流程未把分组标签完整写入每条记录。修复方式是在采集阶段落库组标签，
我们将在下一版实验数据中补齐。

## 六、数据审计过程中发现并修复的问题（如实披露）

1. **评分回填 Bug**：曾因 `topic + group` 模糊匹配，导致部分评审记录回填错位（把正常 7.6–8.3 的值写成 3.7）。
   修复方式：改为 `file_path` 精确匹配。
   **需要说明的残留**：`master_table.csv` 中综合分为 3.7 的记录有 15 条（Bug 痕迹）；
   本目录 `review_db_v3.json` 中只剩 **1 条** 3.7（全库最低值，标准差 0.345、均值 7.95）。
   我们无法确认这 1 条是合法低分还是未清理干净的残留，**如实标注，请复算者注意**。
2. **两个文件来自不同评审批次，不可混用**（重要）：`review_db_v3.json`（563 条：真涌现 325 / 非真涌现 115 / 未判定 123）
   与 `master_table.csv`（566 行：真涌现 320 / 非真涌现 245 / 空 1）**对同一批实验给出了不一致的涌现标记**。
   逐课题比对：两个文件唯一课题数均为 20，其中 17 个课题记录条数相同、可就近比对，
   **这 17 个里有 16 个的真涌现计数不一致**（差异最大的一例：同一课题一文件记 28/75、另一文件记 1/75）。
   此外 `master_table.csv` 的 `v3_emergence` 列取值可达 10 分，而 `review_db_v3.json` 的涌现度维度最高 8 分，
   说明两者不是同一批评审的产物。
   **结论：本材料一律以 `review_db_v3.json` 为准，`master_table.csv` 的涌现标记不作对外口径。**
   早期对外使用的"320/566 = 56.5%"即取自后者，已废止。
3. **涌现度维度样本**：123 份早期记录使用旧格式评审，**不含涌现度维度**（不是"有维度但缺证据"——
   在含该维度的记录里，证据覆盖率是 100%）。故该维度 n=440 而非 563，已在《实验数据表》中标注。

## 八、三个数据文件互相不一致（如实披露）

除 `review_db_v3.json` 外，本包另附**全量原始数据**（见 `实验全量数据/`，含 `experiments_db.json`
与 `master_table.csv`）。我们把它们放在一起核对时发现：**三者对同一批实验的结论不一致。**

| 文件 | 规模 | 真涌现 | 非真涌现 | 未判定 | 涌现度分数范围 |
|---|---|---|---|---|---|
| `review_db_v3.json` | 563 | 325 | 115 | 123 | 4–8 |
| `master_table.csv` | 566 | 320 | 245 | 1 | 6–10 |
| `experiments_db.json` | 566 | 320 | 245 | 1 | 6–10 |

**结构值得注意**：后两个文件互相一致（320/245/1，分数可达 10 分），反而是本材料采用的主数据源
`review_db_v3.json` 与二者都不同（325/115/123，分数最高 8 分）。分数范围不同说明它们是不同批次的评审产物。

`review_db_v3.json` 与 `master_table.csv` 的唯一课题数均为 20，其中 17 个课题记录条数相同、可逐条比对，
**这 17 个里有 16 个的真涌现计数不一致**（差异最大的一例：同一课题 28/75 vs 1/75）。

**本材料仍以 `review_db_v3.json` 为准，理由**：它是唯一带完整判定过程的数据文件——
每条记录含五个角色的分数、置信度与原文依据（2555 个维度实例，证据覆盖率 100%）；
另两个文件只有一个孤立的布尔标记，无法追溯"为什么判为真涌现"。
需要说明的是，按它的口径算出的真涌现率（57.7%）**高于**另两个口径（320/566 = 56.5%），
即我们所选口径**并非更保守的那个**——这一点如实写明，供读者自行判断。
其余两个文件原样附上供核对，不作为口径来源。

## 九、十组汇总表：根因已查明，并已改用可复算口径

材料中曾有一张 10 个实验组的汇总表（V14基础 / V15-A~D / V16-E1~E4 / V17-F）。我们尝试三种途径重建，均失败；
进一步排查后**找到了根因**。

### 9.1 根因：打标签脚本的匹配撞车 bug

数据仓库里的 `backfill_experiments.py` 用"课题关键词 + 人格 + 信息模式 + 干预"给实验打组标签，
但它的循环按 **V15 → V16 → V17** 顺序检查、**命中即返回**。而：

| 冲突对 | 匹配条件 | 后果 |
|---|---|---|
| V15-A ↔ V16-E4 | 最优人格 / 真实信息 / 有干预 | 完全相同，V16-E4 会被判成 V15-A |
| V15-D ↔ V16-E3 | 关闭人格 / 真实信息 / 无干预 | 完全相同，V16-E3 会被判成 V15-D |

再加上该脚本只处理"尚无版本标签"的记录，而 566 条记录的标签来自多批实验运行（部分由运行脚本写入、
部分事后回溯补齐），**标签来源本身不一致**。

**可复算字段的实际分布**：

| 字段 | 实际取值 |
|---|---|
| `experiment_version` | V14 **483** / V15 **64** / V16 **16**（**无 V17**）|
| `experiment_group` | 基础实验 **488** / B **31** / C **1** / D **31** / E1 **15** |
| `master_table.csv` 的 `group` | 基础实验 **488** / B **31** / C **1** / D **31** / E1 **15** |

而原表声称 V15 四组共 163 条、V16 四组共 159 条、V17-F 39 条——**与任何可复算字段都不兼容**。

一个可追溯的线索：原表若干组的 n 与条件目录条数吻合
（V16-E2 的 40 = 共享真实信息_最优人格 40；V16-E1 的 39 = 共享真实信息_关闭人格 39；
V17-F 的 39 = 未知信息源_关闭人格 39）。推测它是把文件系统里的条件目录**拆分重组**得到的，
**而重组过程没有留下脚本，因此无法追溯**。

### 9.2 替代方案：改用可复算的分组口径

按每条记录 `file_path` 中的条件目录（`信息模式_人格模式`）分组——**13 组、563 条、零缺口**，
任何持有本目录数据的人都能一行代码复算：

```python
import json, re
from collections import defaultdict
recs = json.load(open("review_db_v3.json", encoding="utf-8"))["reviews"]
pat = re.compile(r"[\\/]([^\\/]+)[\\/][^\\/]+\\.txt$")
g = defaultdict(list)
for r in recs:
    g[pat.search(r["file_path"]).group(1)].append(r)
```
