# 三臂对照实验 · 预注册设计

> **本文档在跑实验之前写定，跑完后不修改设计，只追加结果。**
> 目的：验证"6 人格团队是否优于同算力预算下的单模型多视角提示"
> 日期：2026-09-15

---

## 一、要回答的问题

**核心问题**：6 人格团队（本系统）产出的决策建议，是否优于同算力预算下"让单模型从多视角分析"的产出？

**为什么问这个**：真涌现率 56.5%~57.7% 只证明了"团队产出 ≠ 单次输出"——但 6 次采样的并集天然超出单次输出，这可能只是采样温度效应。必须与"单模型多视角"做干净对照，才能回答"人格团队是否真的更优"。

---

## 二、实验设计（跑前固定）

### 2.1 题目集（4 题，预注册，中途不换）

| # | 题目 | 类型 |
|---|---|---|
| T1 | 如何提升师范生课堂参与度？ | 教研 |
| T2 | 大学生用AI写作业，学校该禁止还是引导？ | 教研 |
| T3 | Buck变换器输出电压纹波超标，如何改进控制策略？ | 科研 |
| T4 | 分布式缓存的冷热数据分层架构如何设计？ | 科研 |

### 2.2 三臂（每臂每题目跑 2 次种子，共 4×2×3 = 24 次）

| 臂 | 配置 | 说明 |
|---|---|---|
| **A 人格团队** | 6 名成员，认知原型/专业/价值观**各不相同**（现有默认配置） | 当前产品形态 |
| **B 无人格同质副本** | `personality_enabled=False` → 6 名成员配置**完全相同**（引擎走 hunter/计算机/效率默认值） | 隔离"人格差异"这一变量 |
| **C 单模型多视角** | **单次调用**，prompt 要求"从 6 个学科视角分析并输出建议书"，`max_tokens` 给足 | 同算力下的"多视角提示"替代方案 |

### 2.3 同算力控制

- 记录每臂的 **prompt/completion token 总数**（拦截 API usage）；
- 臂 C 的 `max_tokens` 设为**臂 A/B completion 的实测均值**，使输出容量对齐；
- 报告中公布三臂 token 对比，**若差异过大（>2 倍）在结论中标注为限制**。

### 2.4 评价指标（双轨，跑前固定）

**客观指标（不依赖 LLM 评审，可复算）**：
1. **输出字数**（report 长度）
2. **视角覆盖数**：输出中命中的专业维度关键词数（计算机/教育/心理/管理/社会/经济 6 类的词表匹配）
3. **视角均衡度**：各专业关键词命中的分布均匀性（归一化熵）
4. **跨臂文本差异度**：同题不同臂输出的 Jaccard 差异（越低说明越像）

**AI 评审（已知有循环依赖，仅作参考）**：
5. v3 五角色评审综合分（DeepSeek + GLM 双模型）
   —— 报告中**必须标注**："评审与生成同源，存在循环依赖，不作为独立证据"

**人类盲评（本次不做，列为下一步）**：
6. 由团队外评分者对产出盲评（已设计问卷，待发放）

### 2.5 判定规则（跑前定死，跑后不修改）

| 结果 | 结论 | 对应行动 |
|---|---|---|
| A 显著优于 B **且** A 显著优于 C | 人格差异是有效变量 | 保留人格系统，写入材料 |
| A ≈ B（无显著差异） | **人格维度无效** | 按预注册承诺：**砍掉人格复杂度**，卖点收敛到"主教练干预 + 认知盲区" |
| A 优于 B 但不优于 C | "多视角"有效，但"人格差异"不必要 | 改为"多视角提示 + 干预机制"的轻量形态 |
| A 劣于 B 或 C | 人格系统有害 | 同样如实写，并重构产品叙事 |

> **承诺**：无论结果如何均如实公开。若人格被证无效，我们按上表行动——**用结果决定叙事**。

## 三、人格消融（附加实验，同批跑）

在主实验之外，追加以下消融（题目固定 T1、T3，各跑 1 次）：

| 编号 | 消融项 | 配置 |
|---|---|---|
| E1 | 人格全开（基线） | 6 人异构（同臂 A） |
| E2 | 仅认知原型差异 | 专业、价值观统一，仅原型不同 |
| E3 | 仅专业差异 | 原型、价值观统一，仅专业不同 |

**目的**：把"人格"这个笼统概念拆成三个可分别验证的维度，回答"到底哪一维度在起作用"。

## 四、数据留存规范（每日实验通用）

```
experiments/
└── YYYY-MM-DD_实验名/
    ├── PREREGISTRATION.md   本预注册文档（跑前写定）
    ├── manifest.json        实验元数据（时间/设计/参数/成本/环境）
    ├── runs/                每次运行完整输出（JSON，一次一个文件）
    │   └── {arm}_{topic}_{seed}.json
    ├── scores/              评分结果
    │   ├── objective.json   客观指标
    │   └── ai_review.json   AI 评审（标注循环依赖）
    ├── analysis/            统计结果
    │   └── stats.json
    └── SUMMARY.md           人话总结（短句 + 具体数字）
```

**留存原则**：
1. 原始输出**不删不改**（含失败的运行，标注 `status: failed`）；
2. 每个 manifest 记录**实验设计 + 参数 + token 成本 + 代码版本**；
3. 统计脚本随数据一起留存（可复算）；
4. 负结果同样入库。
