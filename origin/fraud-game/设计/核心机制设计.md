# 核心机制设计

## 一、信息银行（线索系统）

### 1.1 线索类型与可信度
| 线索类型 | 可信度 | 说明 |
| :--- | :--- | :--- |
| 直接线索 | 80% | 明确的颜色指向 |
| 间接线索 | 60% | 通过他人言论获得的线索 |
| 模糊线索 | 40% | 不确定性较高的线索 |

### 1.2 线索生命周期
- **开局**：每人获得 1 条线索
- **持有上限**：每人最多 3 条
- **有效期**：当天有效，每天重置
- **来源**：开局分配、少数决奖励、线索交换

### 1.3 线索声称（私聊）
- 玩家可以在私聊中声称持有某条线索（即使没有）
- 声称的线索不可被验证权验证
- 如果被揭穿，信任度大幅下降

### 1.4 线索验证（验证权）
- 验证权是**唯一能 100% 确认线索真实性的工具**
- 每人每局 1 次
- 验证后线索可信度变为 100%（正确）或 0%（错误）

### 1.5 线索调查
- 调查线索来源背景
- 每人每局 2 次
- 不直接验证真实性，提供背景信息

## 二、少数决

### 2.1 触发时机
每天讨论阶段结束后，猜色阶段前

### 2.2 投票规则
- 系统从分层问题池中抽取一个问题
- 所有存活玩家投票（是/否）
- 票数少的那一方获胜（少数派胜利）

### 2.3 奖励
- 少数派获得一条额外线索（可信度 50%）
- 多数派无惩罚

### 2.4 问题池分层
| 天数 | 问题类型 | 示例 |
| :--- | :--- | :--- |
| 第1天 | 信任判断 | "你更相信甲提供的信息，还是乙提供的信息？" |
| 第2天 | 线索评估 | "你认为丙的线索比丁的线索更可靠吗？" |
| 第3天 | 局势判断 | "你觉得当前最可疑的玩家是谁？" |
| 第4天 | 验证判断 | "你认为哪条线索最需要被验证？" |

## 三、公投

### 3.1 触发方式
玩家主动发起

### 3.2 内容
投票决定"哪条线索更可靠"或"验证某条线索"

### 3.3 风险
投错线索会导致该线索被标记为"不可靠"，但不淘汰玩家

### 3.4 与少数决的区别
| 维度 | 少数决 | 公投 |
| :--- | :--- | :--- |
| 触发 | 系统每日固定触发 | 玩家主动发起 |
| 风险 | 低（无惩罚） | 高（线索被标记） |
| 定位 | 信息获取 | 信息验证 |
